# Phases 11–15 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for continuous inline implementation and one final independent review.

**Goal:** Deliver versioned bill assessment, manual claim submission, decisions/Billing confirmation, settlement and a persistent Graphile worker.

**Architecture:** Append validated financial snapshots using the established actor transaction and immutable case events. Add relational remittances/allocations and a private durable queue. Extend the protected case page using native controls.

**Tech Stack:** Next.js/TypeScript, Zod, native PostgreSQL 18/Drizzle, Node tests, Graphile Worker, Codex browser.

**Spec:** [Design](../specs/2026-10-02-phases-11-15-design.md).

## Global constraints

- Native PostgreSQL 5432; no Docker, agent-browser or Playwright invocation locally or in CI.
- Keep applied migrations unchanged, preserve development data/credentials/files and use isolated `_test` connections for fixtures.
- Money is safe integer paise; percentage products use BigInt, half-up rounding; synthetic rule `SYN-DISCHARGE-1` only.
- Access requires active staff and assigned hospital/branch; Billing owns financial sign-off, Desk owns submission/decision, Finance owns receipts/refunds.
- Human authorized continuous implementation; no redundant approval gates. No real integrations or external sending.

## Review focus

1. Changed document revisions, assessments or bills invalidate dependent packs and sign-offs, including stale concurrent tabs.
2. Duplicate keys with changed content fail; duplicate delivery never repeats a financial effect.
3. Shared remittance allocations cannot cross scope, overallocate or attach to stale approval.
4. Rounding/overflow, tariff exclusions and date conflicts cannot invent coverage or patient debt.
5. Worker failures and revoked staff context remain safely visible and recoverable after restart.
