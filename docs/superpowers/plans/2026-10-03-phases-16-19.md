# Phases 16–19 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for independent components and superpowers:executing-plans for controller-owned integration. Work in the sole existing `dev` checkout. The owner authorized proceeding after explanation; do not add another approval checkpoint.

**Goal:** Deliver and verify cloud extraction, reviewed AI assistance, the earlier patient journey, and scoped administration/reporting through Phase 19.

**Architecture:** Reuse current case/document/financial/auth services and append-only history. Add durable AI runs and a private PostgreSQL LangGraph checkpointer to the existing worker; isolate provider boundaries with native fetch. Implement journey and admin/report services in separate files, with root coordinating shared migrations, grants, UI composition and serial DB tests.

**Tech Stack:** Next.js/TypeScript, native PostgreSQL 18, Drizzle, Better Auth, Graphile Worker, LangGraph TypeScript, OCR.space Engine 2 and OpenRouter `qwen/qwen3.8-27b:free`.

**Spec:** `docs/superpowers/specs/2026-10-03-phases-16-19-design.md`.

## Global constraints

- Preserve the original 0000–0009 SQL bytes, development records, credentials and recovery refs.
- No Docker, local OCR, agent-browser, Playwright, alternate text model or external tracing.
- Provider inputs are synthetic and explicitly attested; enforce OCR's 1,000,000-byte/three-page limits and literal evidence verification.
- Current identity/branch/role checks apply before and after asynchronous work; no network call inside a clinical transaction.
- Tests that write PostgreSQL acquire the root's exclusive test slot. Shared schema, journal, grant migration and case-page wiring are root-owned; agents never commit concurrently.
- Keep payer decisions, patient confirmation and all money calculations separate from AI proposals.

## Review focus

1. A document/query changes after provider work begins: stale work must not become accepted evidence or an actionable draft (Tasks 2–3).
2. A worker dies between a saved graph step and business completion: resume without duplicate reviews or consequential actions (Task 2).
3. Apparently successful OCR omits pages or model JSON contains invented citations: reject rather than truncate or trust (Tasks 1–3).
4. Admin/export callers lose access or try another hospital/branch: recheck current scope and expose no clinical data to platform users (Task 5).
5. Revised rules or missing decision evidence: historical snapshots persist while current report values remain unknown where necessary (Task 5).
