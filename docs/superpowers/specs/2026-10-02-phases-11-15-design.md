# Cashless discharge, Phases 11–15

## Intent and constraints

Extend the hospital staff workspace through a complete synthetic manual discharge and settlement workflow, then add a persistent background worker. The human authorized continuous delivery through Phase 15, with questions only for missing input, recurring failures or installation permission. This replaces repeated design approval prompts. Continue in the existing `dev` worktree; preserve the native PostgreSQL data and applied migration bytes. Do not invoke Docker, Vercel agent-browser or Playwright, including through CI. Use Codex's browser for visible UI review and Node HTTP/database checks for repeatable verification.

Use Ponytail's default full level: reuse access transactions, immutable case events, document revisions and native form controls. Financial facts remain separately named. All figures are integer paise, bounded to JavaScript safe integers; percentage arithmetic uses BigInt and half-up rounding. These are fictional rules, not verified hospital or insurance rules. AI cannot grant payer approval or send external submissions.

## Versioned financial records

Add a scoped immutable claim-record ledger for bills, assessments, claim packs, acknowledgements, payer decisions, patient confirmations and patient receipts. Each record carries its actor, recording time, occurrence time, case version, relevant exact record/document IDs and validated payload. Relational hospital/branch/case ownership, append-only triggers, forced RLS and separate Billing/Desk/Finance permissions protect it. No document bytes enter the ledger. Existing tables and history remain intact.

Billing captures a bill revision with a service date, line descriptions, gross paise, explicit excluded paise and authorized hospital reductions. A supported `SYN-DISCHARGE-1` snapshot contains effective dates, deductible, co-pay basis points, benefit limit and optional per-line tariff caps. No overlapping exclusions/reductions. Assessment stores line reasons, gross/eligible totals, deductible, co-pay, cap excess, insurer/patient estimates and the exact bill/rule snapshot. Missing/unsupported rules, conflicts or dates outside coverage yield review blocks and unknown estimates. Revisions preserve earlier snapshots and invalidate affected downstream current views.

## Submission and queries

Desk assembles and approves a frozen claim pack from a current supported assessment, current bill, manually verified required document types (final bill, discharge summary and policy) and exact revisions. Record preparation separately from actual external submission acknowledgement. No payer API or sending integration is introduced. A changed bill, rule assessment or pinned document revision makes the old pack stale. Acknowledgement records require a reference, actual occurrence time and scoped evidence. Duplicate references and idempotency keys cannot append duplicate work.

Reuse separately referenced payer queries and immutable response draft events. A staff-reviewed response acknowledgement pins a specific response event and evidence revision, preserving revised responses and repeated query cycles. Subsequent drafts invalidate the current response acknowledgement. Explicit resolution is recorded with evidence; preparing a draft does not resolve a query.

## Payer decision and patient amount

Desk records the payer's final approval/rejection or conditional decision, exact bill/pack, reference, effective time, source revision and conditions. Conditional/old-bill decisions block confirmation. Authorization remains separate from the deterministic estimate. Billing records an evidenced allocation:

`gross = payer authorization + patient responsibility + hospital reduction + unresolved decision dispute`.

All amounts are nonnegative; an unexplained shortfall cannot be silently assigned to the patient. Billing confirms the current bill/assessment/decision versions and evidence. Verified patient payments, refunds and reversals are separately evidenced immutable records. Before current sign-off, collect/refund are unknown; after it, collect/refund use net patient receipts. Changing a bill, assessment or decision requires a fresh sign-off. Finance executes refunds against current authorized refund amounts; owed and executed refunds are separate facts.

## Remittances and settlement

Finance records a scoped bank/remittance receipt with a unique external reference, evidence, amount and allocations across available claims in that branch. Allocations may be partial; unallocated money remains visible. Sum of allocations cannot exceed the evidence amount. Allocation is tied to an exact valid payer decision, including any preexisting decision dispute. Unmatched receipts do not invent authorization. Reverse receipts using an append-only reversal referencing the original; duplicate imports/reversals have no second effect. Authorized receivable and actual net receipts remain distinct. Overpayments require Finance review. Decision disputes remain open even after the full authorized amount is received.

## Persistent worker

Use pinned Graphile Worker in a separate Node.js process against native PostgreSQL. Queue schema installation is explicit in migration tooling, never opportunistic DDL by HTTP requests. Keep queue access private. Initially support only a deterministic claim-pack validation/review task; model/OCR services begin in Phase 16. Persist request owner, input versions, job status, bounded attempts and useful sanitized recovery reason. Use a transactionally inserted job/outbox and a stable job key; business completion is independently idempotent because queue delivery is at least once. Recheck current staff hospital/branch/permission and input fingerprint when executing; wrong/stale context cannot produce a consequential result. Restart safely resumes queued work. A failed job can be deliberately retried by an authorized owner with an audit trail.

## Completion evidence

Test the five existing fictional packs, exact paise rounding/caps, stale changes, missing evidence, conditional and rejected decisions, wrong roles/tenants/branches, conflicting retries, multiple remittance allocations, duplicate imports and reversals. Test queue stop/restart, repeated delivery, denied context and bounded failure. Review the staff flows in Codex's browser. Run lint, TypeScript, build, server/database/HTTP suites and native GitHub CI. Record evidence for each phase; only then mark Phases 11–15 complete and promote tested `dev` to `main`.
