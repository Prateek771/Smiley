# Phases 16–19 design

## Purpose and authorized scope

Extend the tested hospital claims workspace with cloud document extraction, staff-reviewed evidence-backed drafts, the earlier cashless patient journey, and administration/reporting. The owner authorized continuous implementation through Phase 19 after the readiness audit. Use the sole existing `dev` checkout; preserve current development records and applied migration bytes.

## Constraints

- Native PostgreSQL 18 on port 5432; no Docker, local OCR, Playwright or Vercel agent-browser.
- Cloud OCR: OCR.space Engine 2. Text model: only `qwen/qwen3.8-27b:free` through OpenRouter. Never substitute another model or silently relax routing/data controls.
- Synthetic documents only, with an explicit staff attestation when cloud processing is requested. No external tracing or credential/provider-response logging. Free limits are enforced before upload: 1,000,000 bytes and at most three actual PDF pages.
- Staff, hospital, branch and role checks occur on the server and through RLS. Background work rehydrates current authority before cloud work and before publishing results. Network calls hold no clinical transaction or claim-row lock.
- AI facts and drafts are proposals. They cannot write financial records, patient confirmation, payer decisions, external acknowledgements or bank receipts. Manual evidence and existing financial workflows remain usable during outages.
- All money uses validated exact integer paise. Missing/stale evidence remains unknown, not zero. Preserve request, estimate, actual payer response, patient allocation, dispute and receipt as separate facts.

## Phase 16: extraction and verification

Create scoped durable AI runs separate from existing pack-review jobs, preserving Phase 15 behavior. One run identifies its owner, purpose, exact document revision(s), case version, request fingerprint, source fingerprint, attempts, status and recovery relationship. An immutable review ledger records staff acceptance, correction or rejection of individual facts/drafts. Composite foreign keys and forced RLS prevent cross-case sources and wrong-tenant access.

Run a TypeScript LangGraph graph in the existing persistent Graphile worker. Use the official PostgreSQL checkpointer in private `smiley_langgraph` schema, provisioned explicitly alongside queue setup. Each run has its own thread ID and a per-run execution lock. Checkpoints persist OCR and model stages synchronously; resumption uses the stored pending stage rather than rerunning completed stages. Worker crash recovery and idempotent publishing bridge the separate checkpoint/business transactions.

OCR results retain exact page text and word positions with `confidence: null`; the provider documents no confidence score. Text documents can use their original UTF-8 contents as evidence without local OCR. Reject partial OCR, missing pages, oversized files, malformed results, stale originals and unsupported formats. The bounded PDF worker supplies actual page count while retaining its validation/allocation guards.

The model proposes a short allowlist of fields with a page, literal source quote and literal value. Validate every page/quote/value against OCR evidence locally. Contradictions remain separate proposed facts; uncertain or unsupported output requires review. Facts have no downstream authority until a current authorized staff member reviews them, with original/corrected values and reasons retained.

## Phase 17: checks and response drafts

Use the same run infrastructure for pack checks and payer-query drafts. Freeze current source revisions and query/input fingerprints. Deterministic checks identify missing mandatory document categories; AI can select conflicting facts and source excerpts but cannot declare a pack submitted or approved.

For a response draft, let the model select evidence-backed excerpts and follow-up categories. Render the source excerpts with their citations and a staff-editable draft. Model-selected evidence must exist in the frozen inputs; invented quotes, values, pages and references fail validation. Model wording is never sent externally. Acceptance/correction/rejection is an explicit immutable staff review. Revised documents, changed queries or revoked access prevent approval/publication of stale work. Follow-up suggestions remain local suggestions until staff record a case action.

## Phase 18: earlier patient journey

Reuse append-only `claim_events` rather than add mutable duplicates of eligibility/preauthorization history. Strict typed journey actions cover evidenced eligibility, initial preauthorization request, actual payer response, treatment updates, linked enhancements, repeated payer-query/response/acknowledgement cycles, revised responses and discharge handoff. Every action is optimistic-versioned, idempotent and audited.

Eligibility must cover the relevant admission/treatment date and remain current at request time. Negative/expired/unclear results require review. A requested enhancement amount means the new total requested authorization. Pending enhancements preserve earlier actual authorization; revised responses identify their predecessor. A prepared response is distinct from actual external acknowledgement. Current source revisions and chronological ordering are checked; historical revisions remain visible. These early-journey records do not alter final discharge financial decisions or receipts, and older cases are not retroactively required to acquire them.

## Phase 19: administration, rules and reports

Hospital administration exposes current hospital/branch metadata, invitations/revocation, staff grants/revocation and disabling with existing staff authority. Platform administration uses a separate current-SUPER_ADMIN registry context for hospital/branch metadata and never gains clinical branch access. Do not grant platform roles through hospital administration or disable the last active administrator accidentally.

Introduce approved, immutable hospital/policy rule revisions with separate lifecycle history and optimistic conflicts. Preserve calculation engine version `SYN-DISCHARGE-1`; registry revision is a separate identifier. Billing can select an approved matching policy/date rule loaded server-side; snapshots freeze the rule and its revision. Retirement prevents new selection but never rewrites historical assessments. Retain the existing explicitly labelled synthetic manual snapshot path for backward compatibility.

Desk reports contain assigned-branch work/status/owner/action. Finance reports use current usable financial records and settlement/patient state, keeping estimate, authorization, patient confirmation, dispute, actual receipts and remaining receivable/refund separate. Missing or stale inputs produce null. Export the same scoped DTO through bounded CSV responses; exclude document text, storage keys, contact/policy identifiers and raw payloads, and neutralize spreadsheet formulas.

Report preparation from the first evidenced final bill to the first staff-reviewed pack. Desk resolution starts at that same first bill and runs through the current valid Billing signoff, including payer waits and rework; it never resets. Show submission delay, payer waiting, query response and Billing review separately, including ongoing intervals and an `asOf` timestamp. A missing bill makes the timer unknown. Flag invalid/backdated ordering rather than invent negative durations. Label locally recorded query times and synthetic timing limitations; do not imply the fictional records prove the discharge target.

## Delivery and verification

Add focused server/unit/database/HTTP tests for trust boundaries, idempotency, version changes, outages, incomplete OCR, invented evidence, staff correction/rejection, checkpoints and crash resumption, journey cycles, admin isolation, rule lifecycle, reporting totals and exports. Run database-writing checks serially in the isolated test database. Apply additive migrations to development only after focused checks and a private backup, without reseeding.

Review usable desktop/mobile staff flows through Codex's in-app browser. Record each phase's evidence in `BUILD_PLAN.md`, keep incomplete checkboxes unchecked, run lint/types/full tests/build, review the implementation independently, and push tested checkpoints to `dev`. Promote to `main` only after exact-commit GitHub CI passes. No unresolved provider or production-readiness claim is silently filled in.
